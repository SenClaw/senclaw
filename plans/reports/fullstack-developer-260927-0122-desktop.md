## Contract gaps / design notes (flagged for the daemon side / phase 01 & 06)

Cross-checked against the parallel web-app phase's report — same conclusions, listed once here:

1. **`/api/embedding-config`'s `provider: "local"` wire shape isn't covered by `runtime-protocol.md`** (that route predates the split and sits outside §5). I set `modelName` to the bare `LocalModel.key` prefixed `local:` (`local:<key>`), grounded in §5.5's route (`/api/runtimes/models/<key>/v1/embeddings`) — needs confirmation once the daemon's embedding-config handler is rewritten, since "local" used to mean an in-process candle model name.
2. `POST /api/runtimes/check-updates` and `POST /api/runtimes/install-local` response shapes aren't pinned in §5.1. Neither is read for its fields client-side (the UI just re-fetches `GET /api/runtimes`/`catalog` afterward for the former, calls `onChanged()` for the latter), so a shape mismatch is low-risk either way.
3. `RuntimeInstallJob.state`/`LocalModelDownload.state` aren't typed as closed enums — an unanticipated value renders through `context.tr(process.state)` (falls back to the raw word) rather than an exhaustive switch, so a new state degrades instead of crashing.
4. `PUT /api/runtimes/settings` — unclear whether it accepts a partial patch or needs the full `{autoUpdate, channel, idleTimeoutSecs}` object; the client always sends the full object (reading the two untouched fields off the currently-loaded `RuntimesState`), so it is correct either way.
5. The shared local-models engine settings list ends with "…" in the phase brief (more fields may exist beyond the six exposed here). `LocalModelsSettingsCard` exposes exactly `temperature/top_k/top_p/max_new_tokens/max_kv_tokens/enable_thinking` and round-trips every other key it received untouched, so nothing is silently dropped — but nothing beyond those six is editable from this screen yet.
6. Whether an `InstalledRuntime` with `versions.length > 1` is actually a state the daemon produces (vs. always collapsing to the newest until the old one is fully idle-reaped) isn't pinned by the doc — I built the kebab's per-version uninstall defensively against §7.3's "the old version stays installed until the user removes it" wording, but haven't seen a live daemon confirm the shape.

### Fixes, by file

**`lib/core/transport/api_client.dart`** — `post()` gained an optional `Duration? timeout` parameter (mirrors `get()`), so a single slow call can opt out of the 30s default without a new method.

**`lib/features/settings/local_models_section.dart`** (the bulk of the work):
1. **Embedding preset / bare key** — see settings_screen.dart below; this file just exposes `m.key` for the picker to use.
2. **Download state vocabulary** — `LocalModelDownload.active` now includes `listing` (was only `queued|downloading`, so a download stuck in the daemon's "listing files" phase looked finished and stopped polling/offering Cancel). Added `.failed` (`state == 'failed'`) and a new `_DownloadFailedRow` that shows the repo + `download.error` in red instead of the row silently vanishing once `active` turns false.
3. **Timeout + runtime-missing on load** — `_load()` now passes `timeout: const Duration(minutes: 11)` (llama.cpp's health gate budget is up to 600s per §3.2). `_act()`'s catch now checks `runtimeMissingFrom(e)` and shows `showRuntimeMissingSnack` instead of a bare toast for any 503 runtime-missing (load/unload/delete alike) — closes fix #11 (the daemon's structured 503 on a failed load was being shown as raw text).
6. **Engine settings are a true partial merge** — `defaultContextLength` is now omitted from the PUT body when the field is empty (was always sent, `null` when blank). `enable_thinking` is sent only when it existed in the loaded `engine` object or the user flipped the switch this session (new `_enableThinkingKnown` tracks that tri-state) — previously a bare `bool` field meant every save injected `enable_thinking: false` for a model that never set it.
7. **Delete offers force-retry on 409** — `_delete`/`_deleteAttempt` mirror `runtime_catalog.dart`'s uninstall-while-running confirm: first attempt with no `force`, and on a 409 (loaded) show a second confirm ("Unload and delete?") before retrying with `?force=1`. **Also removed the Delete button's `|| model.loaded` disable condition** — the button used to be hard-disabled for a loaded model, which made this whole flow unreachable through the UI; deleting a loaded model is now allowed and the 409 path is what handles it.
8. **Download dialog gating** — added `_lookupDone` (cleared on every repo edit, set only after a *successful* `hf-files` lookup). The Download button is disabled until `_lookupDone` and whenever `_format == 'unknown'` (was: enabled as soon as the repo field was non-empty, even before any lookup, and for a format the daemon can't download).
9. — (dead `modelPath` field lived in settings_screen.dart, not here.)

**`lib/features/settings/runtime_section.dart`**:
5. **Catalog refresh on channel change** — `_saveSettings` now also invalidates `runtimeCatalogProvider` when `channel != null` (a channel switch changes which version each catalog entry resolves to; the auto-update toggle alone doesn't need this, so it's conditional on `channel` being passed).
10. **Selections send `version: null` by default** — `_selectSlot` now sends `version: null` ("track newest", per the doc's own words on what a normal pick sends) unless the slot's `candidates` list actually contains more than one version of the chosen id, in which case picking one is a genuine pin and its exact version is sent.
